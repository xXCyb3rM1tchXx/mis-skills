# Visual System — Prospect Intelligence Book & Sales Handoff

All Stage 11 Handoffs MUST share the same professional visual grammar.
The validated Grupo Xcaret deliverable is the historical visual benchmark. The user does not need to attach it.

## Page
- Letter portrait: 8.5 × 11 in.
- Margins: top/bottom 0.55 in; left/right ~0.62 in.

## Typography
- Body: Aptos 9.5 pt.
- Title: Aptos Display 22 pt bold, #1F4E79, centered.
- Account name: 17 pt bold, #2F5597, centered.
- Heading 1: Aptos Display 15 pt bold, #1F4E79.
- Heading 2: Aptos Display 12 pt bold, #2F5597.
- Heading 3: Aptos Display 10.5 pt bold, #4472C4.
- Small control/state note: 8 pt gray.

## Header / footer
Header:
[OFFERING_COMPANY] | Prospect Intelligence Book | [ACTIVE_ACCOUNT]
8 pt gray, right aligned.

Footer:
Uso interno comercial | [Month Year] | [page number]
8 pt gray, centered.

## Cover
Professional and restrained.
Main title centered.
Account name below.
Campaign / offering company / solution / state metadata centered.
Use the same blue hierarchy. Do not create decorative variations account by account.

## Tables
Native tables only.
- Style: clean grid / Table Grid equivalent.
- Header fill: #1F4E79.
- Header text: white, bold, 8–8.5 pt.
- Body: 8–8.5 pt.
- Alternating rows: white / #F3F6FA.
- Fine dark borders.
- No clipped text or broken cells.

## Non-table blocks
Stakeholder cards and Unknown Data Register use Normal text.
Names/labels may use bold and blue accents, but must NOT become Heading styles.

## Consistency
Do not mix font families, palettes or unrelated table styles between accounts.
Do not make the document decorative. It is an executive commercial intelligence artifact.
Preserve whitespace and scanability.
CRM Handoff remains the first substantive section.

## VISUAL_SYSTEM_GATE
Before delivery verify:
1. cover hierarchy;
2. header/footer;
3. H1/H2/H3 hierarchy;
4. body typography;
5. table colors, typography, native rendering and banding;
6. stakeholder/unknown blocks use Normal text;
7. no raw Markdown;
8. no clipping, overlap, broken tables, orphaned headings or unreadable page breaks.

If the host can render DOCX, visually inspect every page.
If rendering is unavailable, apply the system deterministically and report that visual inspection was not performed; never fake visual QA.

Content Quality PASS does not override VISUAL_SYSTEM_GATE FAIL.
